# 07 - Conversation export

## Goal

From the chat header, the user clicks a Download icon and saves the selected conversation as a single Markdown file through the native save dialog. The file contains the conversation title, created/updated timestamps, tags, and every message in order with its role preserved, plus assistant provider/model/thinking metadata, a collapsible thinking section when reasoning exists, attachment names, and error text. Messages are loaded on demand when needed, the button refuses to produce an empty or mid-turn snapshot, and cancel writes nothing. No new Rust command, no schema change, no import path.

## Assumptions and decisions

- **Verified current state.** `src/components/chat/chat-header.tsx` renders `SidebarTrigger`, the title, a pin icon button (`variant="ghost" size="icon-xs"`), and `TagEditor`, inside a right cluster `div.flex.shrink-0.items-center.gap-1`. `src/lib/download.ts` exports `sanitizeFilename` and `downloadString(content, defaultName, mimeType): Promise<boolean>` (Tauri `save()` dialog, then `invoke("write_file")`; returns `false` on cancel, throws on write failure). `write_file` is already registered in `src-tauri` (ARCHITECTURE.md section 6), so nothing is added to Rust. `src/lib/types/chat.ts` defines `Message` (`role`, `content`, `reasoning?: ThinkingBlock`, `status?`, `error?`, `editedAt?`, `createdAt`, `model?: MessageModelInfo`, `thinkingLevel?`, `attachments?: Attachment[]`) and `Conversation` (`title`, `tags`, `createdAt`, `updatedAt`, `messages`).
- **Lazy loading is real, and the guard must be inside the hook.** `loadHistory` builds every conversation with `messages: []`. `selectConversation` starts `loadMessagesForConversation`, and `loadMessagesForConversation` swallows load errors in an empty `catch` and returns `void` without adding the id to `loadedConversationIds`. So "did the load actually succeed" can only be answered by re-reading `loadedConversationIds` after the await, not by the promise resolving.
- **`loadMessagesForConversation` is already idempotent.** It returns immediately when the id is in `loadedConversationIds` or `messagesLoading`, so the export handler can call it unconditionally when the id is unloaded without racing the selection load.
- **Snapshot completeness guard.** Export is disabled while the selected conversation has an in-flight turn or its messages are still loading. Plan 01 provides the authoritative signal `useChatStore(state => state.conversationActivity[conversationId])`; until that lands, the fallback is `messagesLoading.has(id)` plus any loaded message with `status === "streaming"`. Documented gap without plan 01: the compaction window before the assistant message exists is not covered (same accepted gap as plan 03). Plan 07 reads the activity slice only if it exists in `ChatState`; adding an optional-chained property that `ChatState` does not declare would not typecheck.
- **Reasoning and attachments are session-only, and the export says so by omission.** `saveMessage` in `src/lib/turso-repository.ts` has an explicit column list with no `reasoning` and no attachments, and `loadMessages` cannot restore them. So a thinking section and attachment names appear only for messages created in the current app session. This matches the UI exactly (a reload also loses the thinking block and attachment chips). The export never tries to embed attachment data.
- **Tool-call counts are skipped by design.** Plan 02's `messageToolActivity` is transient and not persisted, so an exported file would silently disagree with the next app launch. Not included, not faked.
- **Markdown is the only format.** No JSON, no import, no format selector, no dropdown. A single 24px icon button is both the smallest and the most discoverable option for one format. A future JSON format is the trigger to convert this into a `DropdownMenu`, which is explicitly deferred.
- **Formatting is separated from side effects.** `src/lib/export-conversation.ts` is pure (no store, no Tauri, no toast) so the document content can be inspected by reasoning and reused, and `src/hooks/use-export-conversation.ts` owns load/guard/save/toast. `chat-header.tsx` only renders a button.
- **No new named contract is warranted in `src/lib/export-conversation.ts`.** It takes an existing `Conversation` and returns a `string`; a sibling `.types.ts` would only hold invented aliases for a single signature, which `CODING_STYLE.md` forbids. `ChatHeaderProps` stays a local interface in the component file like the existing props, and the hook returns an untyped object literal like `useChat()` and plan 03's `useForkConversation`.
- **Filename is built here and sanitized twice, harmlessly.** `buildExportFilename` uses `sanitizeFilename` per the requirement; `downloadString` sanitizes the same string again (idempotent). The base name must be passed **without** extension because `downloadString` appends `.md` (`extFromMime("text/markdown")` -> `md`, Markdown filter).
- **Stable date stamp.** The stamp uses the conversation's `updatedAt` formatted in **local** time as `YYYY-MM-DD`, computed with `getFullYear`/`getMonth`/`getDate` rather than `toLocaleDateString` (which yields slashes) or `toISOString` (which can shift the day). `createdAt` and `updatedAt` with times still appear inside the document, so nothing is lost.
- **No automated tests.** Project rule: the user tests manually. `npm run lint` (`biome check`) and `npm run build` (`tsc` + Vite) are the gates; a manual checklist replaces the test milestone.

## Proposed structure

```text
src/lib/
  export-conversation.ts          (new) pure Markdown document + default filename
  download.ts                     (existing) sanitizeFilename, downloadString, write_file
src/hooks/
  use-export-conversation.ts      (new) load -> guard -> format -> save -> toast
src/components/chat/
  chat-header.tsx                 (existing) Download icon button, tooltip, aria-label
  chat-area.tsx                   (existing) instantiate the hook, pass onExport/exportDisabled
ARCHITECTURE.md                   (existing) read-only export path, module list
README.md                         (existing) one feature line
```

Responsibilities:

- `export-conversation.ts` owns the document shape. Exports `formatConversationMarkdown(conversation: Conversation): string` and `buildExportFilename(title: string, date: Date): string`; private helpers `formatLocalStamp`, `singleLine`, `formatAssistantMetadata`, `formatThinkingSection`, `formatAttachments`, `formatErrorBlock`, and `roleLabel` stay in the same file because they all serve one document format.
- `use-export-conversation.ts` owns orchestration only: read store state, ensure messages are loaded, refuse busy/empty, call the two pure functions, call `downloadString`, and translate the boolean and any throw into toasts.
- `chat-header.tsx` gains two props and one button; no formatting logic and no store access.

Data flow:

```text
ChatHeader Export button
  -> useExportConversation.exportConversation()
     -> guard: in-flight ref, busy (activity | streaming | messagesLoading), empty
        -> loadMessagesForConversation(id) when not in loadedConversationIds
           -> re-read store: still selected? loaded? messages.length > 0?
              -> formatConversationMarkdown(conversation)   (pure)
              -> buildExportFilename(title, updatedAt)      (pure)
                 -> downloadString(markdown, name, "text/markdown")
                    -> save() dialog -> cancel (no toast) | dest
                       -> invoke("write_file")
                          -> toast.success("Conversation exported")
```

## Milestone 1: Save the open conversation as Markdown

### Outcome

Open a conversation with several messages (a title, some tags), click the new Download icon in the header, pick a location in the native save dialog, and get `Trip planning-2026-02-14.md` on disk. Opening it in any Markdown viewer shows the title heading, created/updated timestamps, tags, message count, and every message in order under its role heading with its content intact. Cancelling the dialog writes nothing and shows no toast. Clicking Export on a brand-new empty conversation is not possible because the button is disabled.

### Implementation

1. `src/lib/export-conversation.ts` (new):
   - `export function buildExportFilename(title: string, date: Date): string` (documented). Steps: `singleLine(title)` -> `sanitizeFilename(...)` -> `slice(0, 200)` (leaves room for `-YYYY-MM-DD` plus `.md` inside the 255-char component limit) -> `${base}-${formatLocalStamp(date, "date")}`. When `title` is blank, `sanitizeFilename` already falls back to `untitled`. When `date` is an invalid `Date` (`Number.isNaN(date.getTime())`), use `new Date()`. Contract in TSDoc: returns a base name **without** extension.
   - `export function formatConversationMarkdown(conversation: Conversation): string` (documented). Document shape, in order:
     - `# ${singleLine(conversation.title)}`
     - blank line, then a metadata list: `- **Created:** <stamp>`, `- **Updated:** <stamp>`, `- **Tags:** a, b` only when tags exist, `- **Messages:** <count>`
     - blank line, `---`, blank line
     - for each message: `## <RoleLabel>` (`User`, `Assistant`, `System`, capitalized from `message.role`), blank line, `message.content` verbatim, blank line, `---`, blank line
     - a single trailing newline at the end of the file
     - `loadMessagesForConversation` in `src/store/chat.ts` already returns messages in stored order, so the formatter does not sort.
   - Private helpers: `singleLine(value: string): string` (collapse all whitespace runs including newlines to single spaces and trim, so a heading cannot be broken by a pasted multi-line title); `formatLocalStamp(date: Date): string` returning `YYYY-MM-DD HH:mm` from local getters with zero padding; `roleLabel(role: MessageRole): string`.
   - Guard: a message with empty `content` (an assistant message that errored before producing text) still gets its role heading and a `*(no content)*` line so the document never has two adjacent separators with nothing between them.
   - TSDoc on every exported and private declaration; no store, no `download`, no toast, no React import.
2. `src/hooks/use-export-conversation.ts` (new):
   - `export function useExportConversation(): { exportConversation: () => Promise<void>; canExport: boolean }` (documented).
   - Selectors: `const conversation = useChatStore(selectSelectedConversation);`, `const isMessagesLoading = useChatStore((state) => (conversation ? state.messagesLoading.has(conversation.id) : false));`, `const isMessagesLoaded = useChatStore((state) => (conversation ? state.loadedConversationIds.has(conversation.id) : false));`, plus the turn-activity selector described under Milestone 2.
   - `const inFlightRef = useRef(false)` with a documented purpose comment: a save dialog takes longer than a render, so it prevents a second dialog from opening before React re-renders the disabled button.
   - `exportConversation` body: return when `inFlightRef.current`; read `useChatStore.getState()` and `selectSelectedConversation(state)`; return silently when there is no conversation; when the conversation is loaded and `messages.length === 0`, `toast.error("Nothing to export yet", { description: "Send a message in this conversation first." })` and return; set the ref; `try` `const markdown = formatConversationMarkdown(conversation);` `const name = buildExportFilename(conversation.title, conversation.updatedAt);` `const saved = await downloadString(markdown, name, "text/markdown");` `if (saved) { toast.success("Conversation exported"); }` `catch` `toast.error("Failed to export conversation")` `finally` clear the ref. Cancel returns `false` and produces no toast.
   - `canExport`: `Boolean(conversation) && !isExporting` in this milestone, extended in Milestone 2. Derive `isExporting` from the ref via a state flag only if the disabled state must update immediately; simplest is a `useState<boolean>` mirroring the ref, set in `try/finally`, so the button actually renders disabled during the dialog.
3. `src/components/chat/chat-header.tsx`:
   - Extend `ChatHeaderProps` with `onExport: () => void; exportDisabled?: boolean;` (documented, same shape as plan 03's `onFork`/`forkDisabled`).
   - Import `DownloadIcon` from `lucide-react`.
   - Inside the existing `div.flex.shrink-0.items-center.gap-1` cluster, add a `Tooltip` + `TooltipTrigger asChild` + `Button variant="ghost" size="icon-xs"` with `aria-label="Export conversation as Markdown"`, `disabled={exportDisabled}`, `onClick={onExport}`, `<DownloadIcon className="size-3.5" />`, and `<TooltipContent>Export as Markdown</TooltipContent>`. Place it as the first child of the cluster. When plans 03 and 06 land, the final order is `fork, export, usage meter, pin, tags`: fork and export are conversation operations, the usage meter is a metric, and pin/tags remain the organization controls at the end. Do not touch the title element (`min-w-0 truncate text-sm font-semibold flex-1`) or the cluster's `shrink-0`.
4. `src/components/chat/chat-area.tsx`: `const { exportConversation, canExport } = useExportConversation();` and pass `onExport={exportConversation} exportDisabled={!canExport}` to `ChatHeader`. Nothing else changes.

## Milestone 2: Only complete, non-empty snapshots

### Outcome

Export is impossible while the conversation is generating or its messages are still loading, and it is impossible while the conversation has no messages. If the selected conversation's messages were never loaded (for example a load that failed), clicking Export loads them first and exports the full history instead of writing an empty or partial file. If that load also fails, the user gets an error toast and no file is created.

### Implementation

1. `src/hooks/use-export-conversation.ts`:
   - Turn activity: when plan 01 has landed, `const isTurnActive = useChatStore((state) => (conversation ? Boolean(state.conversationActivity[conversation.id]) : false));`. If plan 01 has not landed, omit this line and rely on the fallback; add it as one extra condition when plan 01 ships (same rule plan 03 documents).
   - Documented local helper `isConversationBusy({ isTurnActive, isMessagesLoading, messages }): boolean` returning true when any of: turn active, messages loading, or a message with `status === "streaming"`. Keep it local to the hook for now; if plan 03 has landed, move the identical predicate into `src/lib/conversation-busy.ts` with a sibling `.types.ts` holding a structural `ConversationBusyInput` type and have both hooks import it, so two features cannot drift.
   - In `exportConversation`, after the no-conversation check: when busy, `toast.error("Wait for the current response to finish")` and return. Read `const state = useChatStore.getState()` again before the busy check so the guard sees the latest render-independent state.
   - Lazy-load path: `if (!state.loadedConversationIds.has(conversation.id)) { await state.loadMessagesForConversation(conversation.id); }` then re-read `selectSelectedConversation(useChatStore.getState())`. If it is now `null` (deleted during the load), return silently. If `!loadedConversationIds.has(id)` after the await, `toast.error("Failed to load conversation", { description: "Its messages could not be read. Try again." })` and return. If `messages.length === 0`, use the existing "Nothing to export yet" toast. Only then format and save. This ordering is the guarantee that the formatter is never reached with an unloaded or empty message list.
   - `canExport`: `Boolean(conversation) && !isExporting && !isBusy && (isMessagesLoaded ? conversation.messages.length > 0 : true)`. An unloaded conversation stays enabled because clicking it performs the load. This mirrors plan 03's `canFork` expression so the two header actions agree about busy state.
   - TSDoc on the helper and on the guard branch explaining why `loadedConversationIds` is re-read (a swallowed load error in the store).
2. `src/components/chat/chat-header.tsx`: no change; it already takes `exportDisabled`.
3. No change to `src/store/chat.ts`, `src/lib/download.ts`, `src/lib/turso-repository.ts`, `src-tauri`, or the schema.

### Verification

1. `npm run lint` and `npm run build` pass.
2. Send a prompt and click Export while the answer streams: the button is disabled for the whole turn, including the thinking phase, and is enabled again once the answer completes or the turn errors or is stopped.
3. Select a conversation whose messages are still loading (slow network or a large history): the button is disabled while the message spinner is visible, then enabled.
4. With another conversation streaming, select an idle conversation and export it: it works, and the file belongs to the idle conversation.
5. Offline load-failure path: open devtools network throttling or take the app offline, select a conversation that is not yet loaded (for example an entry loaded from a month group) so its load fails silently, then click Export. Expect the "Failed to load conversation" toast, no file, and no empty document. Bring the network back, click Export again: the messages load on demand and the saved file contains the full history.
6. Delete the selected conversation in the split second the save dialog is open (delete from the sidebar behind the dialog): no crash and no stale file content is written from a conversation that no longer exists.
7. Double-click Export rapidly: exactly one save dialog opens.
8. Empty conversation: button disabled, and a programmatic call path still produces the "Nothing to export yet" toast rather than an empty file.

### Deliberately deferred

- Detecting and waiting for a turn started in a conversation that was never selected in this session (impossible today: turns only start in the selected conversation).
- Queuing the export until the current turn finishes ("Export after this turn") - explicitly rejected; waiting is better than surprising the user.
- Covering the compaction window without plan 01 (documented gap).

## Milestone 3: Assistant metadata, reasoning, attachments, errors

### Outcome

The saved file is a faithful document of what the UI showed: each assistant message carries a `*Provider / Model - Thinking: level*` line matching the bubble, a collapsed `<details><summary>Thinking</summary>` block when reasoning exists, attachment names for messages that had them, edited markers, and the error text for messages with `status === "error"`. Rendered on GitHub or in any Markdown viewer, the thinking section is collapsed by default and the error is a visible blockquote.

### Implementation

1. `src/lib/export-conversation.ts`, inside the per-message section, in this exact order after the role heading:
   - Assistant metadata line, only when `message.role === "assistant" && message.model`:
     ``*`${model.providerName}` / `${model.modelName}`${thinkingSuffix}*`` where `thinkingSuffix` is `` ` - Thinking: ${message.thinkingLevel}` `` only when `thinkingLevel` exists and is not `"off"`. Keep the wording identical to `message-bubble.tsx` so the document and the UI agree, wrapped in backticks so provider/model names with underscores or asterisks render literally.
   - Thinking section, only when `message.reasoning?.content.trim()`:
     ```md
     <details>
     <summary>Thinking</summary>

     <reasoning content verbatim>

     </details>
     ```
     The blank line after `</summary>` is required for the body to render as Markdown inside the collapsible block.
   - Attachments: `*Attachments:* name1, name2` built from `message.attachments.map((a) => singleLine(a.name))`, only when the array is non-empty. Never read or embed `attachment.data`; add `(contents not included)` at the end of the line so a reader knows the file is text-only.
   - `message.content` verbatim, or `*(no content)*` when blank.
   - Edited marker: `*Edited ${stamp}*` when `message.editedAt` exists, mirroring the bubble's "Edited" label. Include it because a silently edited transcript would be misleading.
   - Error block last, only when `message.status === "error"` and `message.error`: `> **Error:** <text>` where every line of the error text is prefixed with `> ` (helper `formatErrorBlock`), so multi-line provider bodies stay inside one blockquote.
   - Helper signatures documented: `formatAssistantMetadata(message: Message): string | null`, `formatThinkingSection(reasoning: ThinkingBlock): string | null`, `formatAttachments(attachments: Attachment[]): string | null`, `formatErrorBlock(error: string): string`. Each returns `null` when it does not apply so the message body assembly stays a flat list of non-null blocks joined by blank lines.
   - Do not include tool-call counts, message ids, conversation id, or status for non-error messages.
2. No hook or component change.

### Verification

1. `npm run lint` and `npm run build` pass.
2. Start a turn with a reasoning model at `low`/`medium` thinking, let it finish, then export: the file contains the italic provider/model/thinking line and a `<details>` block whose body is the reasoning text; in the GitHub preview (or VS Code Markdown preview) the block is collapsed by default.

### Deliberately deferred

- Fence-aware protection against an unterminated code fence in one message swallowing the next role heading. Content is preserved verbatim per the requirement; a heuristic escape layer is a separate decision.
- Exporting the persisted compaction summary as a section.
- Restoring reasoning/attachments from storage (would require a schema change and is explicitly out of scope).
- Per-message export changes in `message-bubble.tsx` (the existing single-message download stays as is).

## Completion criteria

- The chat header exposes a Download icon button with a tooltip and an accessible label, and it produces one Markdown file via the existing save dialog and `write_file` path with no new Rust command.
- The exported document contains the title, created/updated timestamps, tags when present, and every message in order with role headings and verbatim Markdown content.
